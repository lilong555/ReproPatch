# SDK 基础契约

当前版本：**0.2.0.dev5，P1-04 已验收**。生产自动入口见 [P1-05](P1-05.md)。
核心 `verify-patch` 保持不加载模型模块、SDK 或凭据。

## 安装与公开入口

`pip install -c requirements/agent.txt '.[agent]'` 安装固定组合：
`openai-agents==0.24.0`、`openai==3.35.1`、`httpx2==2.15.1`、`pydantic==2.14.1`。
完整传递依赖及平台标记在 `requirements/agent.txt`，解析锁与包哈希在 `uv.lock`。
缺失 extra 返回 `ENGINE_DEPENDENCY_MISSING`，主 SDK 版本不匹配返回 `SDK_VERSION_MISMATCH`。

`models.responses_model` 是异步上下文管理器，拥有并关闭 AsyncOpenAI 及传输，
返回公开 OpenAIResponsesModel；模型名、端点、指定 key 环境变量和付费授权必须显式有效。
不提供默认模型、自动端点探测或 Chat Completions 转译。

`agent_runtime.run_sdk` 接收已构造的 SDK Model、原生 input Items、静态 function tools、
公开 hooks/input filter 与明确限额，只调用一次 `Runner.run`，返回原生 RunResult。
没有本项目的 SDK Model 基类、step parser、Session 数据库、worker 或第二套循环。

Runner 对话循环与工具执行的责任见 [官方 SDK 文档](https://developers.openai.com/api/docs/guides/agents/sdk)，
原生运行结果和继续输入见 [官方运行指南](https://developers.openai.com/api/docs/guides/agents/running-agents)。
本项目的具体签名与行为由固定安装版本的公开 API 和离线契约共同验证。

## 配置与数据

- AsyncOpenAI 显式 `max_retries=0` 与有限 timeout；默认传输不继承代理，不跟随重定向。
- ModelSettings 显式 `store=False`、`parallel_tool_calls=False`、`preserve_raw_usage=True`、
  `response_include=["reasoning.encrypted_content"]`、输出 token 上限、模型 timeout 和 never retry。
- RunConfig 关闭 tracing 与敏感数据追踪，function tool 并发为 1，未知工具报错；全局 tracing 也关闭。
- 不配置 Session、previous_response_id、conversation_id、handoff、hosted tools、MCP 或远程工具。
- 原生 message/function_call/function_call_output/reasoning 保持原类型和关联 call_id；
  encrypted_content 经下一请求及 `to_input_list()` 保持不透明值，不归一化为四 role。
- 用量只从公开 ModelResponse.raw_usage 提取；缺失字段为 null，显式整数零为零。
  SDK Usage 的累计缺省零不能充当已知消耗；fake 用量属于合成测试值，费用未知。

## 脚本

`load_sdk_script(Path)` 只读取普通文件，拒绝最终 symlink/FIFO/目录；最多 256000 bytes。
JSON 不允许重复键、非有限数；顶层恰为 `version` 与 `steps`，version 是整数 1，步骤为 1–100 个。
每步必须有 output 列表，可选 usage；不接受其他字段。
每个 output 经公开 ResponseOutputMessage 或 ResponseFunctionToolCall 严格校验，最多 32 项。
usage 只允许 input_tokens/output_tokens/total_tokens 非负整数，bool 不算整数。
加载器构造公开 ModelStep/Usage/ScriptedModel，不把原始 dict 当作 SDK 输出对象。

```json
{"version":1,"steps":[{"output":[{"id":"done","type":"message","role":"assistant","status":"completed","content":[{"type":"output_text","text":"完成","annotations":[]}]}]}]}
```

reasoning、延迟和故障契约通过 pytest 中公开 ModelStep/responder 构造；文件不能加载 Python 模块、
表达式或 callback。脚本耗尽仍请求时异常退出，不自动补“完成”；测试结束必须 assert_complete。
CLI fake 引擎使用此原生脚本格式。

## 准入、异常与取消

离线测试证明：input filter → on_llm_start → on_llm_end → 工具回调 → 下一请求。
on_llm_end 可以检查整个响应并抛异常，两个工具调用均不会执行；合法多调用仍串行执行。
工具使用 `failure_error_function=None`；SDK UserError 包装的 ReproPatchError 通过公开异常链重新抛出。
基础设施错误不变成成功的工具结果。其他 SDK 错误维持原生类型；API 错误只暴露安全分类。

模型限时为公开 ModelTimeoutError，外层限时为 TimeoutError，主动取消为 CancelledError。
异步主体接收取消；SDK 可以再次取消异步 finally，返回时也可能仍有 SDK 收尾任务。
因此 run_sdk 不是资源清理屏障：外层 Run 拥有容器、工作树和独立清理预算，负责确认代码停止与资源删除。
基础入口不创建线程；真正 async 工具由宿主静态注册保证，SDK 包装器自身为 async 不能证明内部回调没有线程。
生产六工具的取消、预算和资源交接见 [P1-05](P1-05.md)。

## 凭据与证据

无授权在加载 SDK、读取 key 或创建客户端前拒绝。HTTPS URL 不允许 userinfo、query、fragment 或控制字符。
凭据不进入可序列化 context；SDK 模型/工具/客户端日志关闭，即使宿主开启 DEBUG。
离线 HTTP 401/403/429/500/307、连接和读超时均只有一次请求，错误体与 request_id 中的虚拟密钥不外泄。
MockTransport 不进行真实网络，测试拒绝 socket 连接；未执行付费模型或 V-LIVE。

执行证据与安装验收见 [测试报告](TEST_REPORT.md)。
