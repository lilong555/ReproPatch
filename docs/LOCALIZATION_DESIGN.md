# 执行反馈驱动定位

## 结论与范围

定位接口提供文件级命中摘要与有界下钻 B，以及使用模型可见编译、测试与栈证据排序的 C；A 保留原生文本搜索。
主流程依靠授权文本检索、源码窗口和可追溯执行回执运行。Tree-sitter 保留在独立的可选语法查询模式，A/B/C 共用文本工具链。
[生产实现](../src/repropatch/localization.py)、[运行时接线](../src/repropatch/localization_runtime.py)、[离线微基准](../benchmarks/localization-offline/README.md)及[独立配对实验](../benchmarks/localization-ablation/README.md)均提供可复现入口。模型定位表现和冷验证收益由在线实验测量。
决策依据是分层检索的文献支持及本仓库静态测量；执行证据排序在 C++ 中的增量价值由 C/B 配对实验评估。

## 本仓库事实与接口

[静态报告](../benchmarks/code-index-20261106/report.md)固定三份 fmt 头文件与 12 个预登记符号目标：原生搜索覆盖 12/12、Tree-sitter 结构查询覆盖 11/12，返回体积分别为 6,419 与 42,518 bytes。
两组采用相同符号字符串和授权范围，分别返回命中行与语法记录；体积为 runtime 包装及折叠前的规范 UTF-8 JSON。覆盖规则分别核对目标锚点行与定义的位置、符号及类型。
该小型定向样本模型调用为零，结果集均无截断；14 条结构预览达到长度上限。它描述这批静态查询，真实定位调用、token、冷验证及跨任务优劣仍待测量。

| 现有入口 | 已有契约 | 本设计衔接 |
| --- | --- | --- |
| `Toolbox.search_code(query, path=".")` | 大小写敏感的字面匹配；最多 100 个命中行，每行预览 300 字符，序列化响应上限 64 KiB；触及限额即返回 `truncated` | A 原样冻结；B/C 复用匹配语义与授权读取，另设截断前聚合层。 |

## B：文件摘要与有界下钻

B 的入口为 `search_files(query, path=".", cursor=None)`；使用原有 `read_file` 下钻，游标绑定查询、范围、源码及检索配置。
聚合直接消费授权源码的匹配流，在摘要输出截断之前按文件累计命中行数；独立扫描器复用现有匹配规则，避免仅聚合 `search_code` 已返回的前 100 行。
每个扫描块最多读取 16 MiB、128 个文件；每页最多展示 12 个候选文件及每文件 8 个命中行号。工具原始响应默认上限为 64 KiB，正式配置设为 22 KiB，为运行时包装预留空间。B/C 按共同候选池的最大记录尺寸及相同证据预留计算页容量，保证相同预算下的分页公平性。
命中索引采用最多 8 个扫描块、64 MiB 的有界 LRU 缓存，分页及密集行号续查复用已扫描索引；源码变化立即失效，恢复后按需重建。扫描字节、文件数、元数据检查、缓存命中、墙钟、排序时间及响应字节分别记录。
文件候选包含 `path`、`match_count`、有限 `hit_lines`、候选 ID 与来源；摘要返回 `query`、`scope`、匹配文件总数、`scan_complete`、`truncated`、`next_cursor`。
扫描完整时报告精确计数；提前终止时报告已观察下界与 `count_is_lower_bound=true`，区分“尚未扫描”和“已扫描但未展示”。
候选展示保持有限，游标可继续扫描或分页；游标绑定查询、范围、源码哈希和扫描状态。源码变化后重新查询，避免沿用失效偏移。
下钻先用已知路径和命中位置选择窗口，再调用现有 `read_file`；文件内查询复用字面搜索，密集命中通过同一聚合扫描层续查，保留超过前 100 行的访问通路。
默认读取仍为 200 行、单次最多 400 行；摘要阶段主要展示路径、计数与位置。任何实际源码片段都进入统一曝光计量。
候选耗尽后可继续分页、收窄或扩展授权目录、修改关键词、直接读取已知位置；每次工具调用及参数保存在同一轨迹中，并计入总预算。
语法边界辅助作为独立可选研究项；主实验三臂关闭该辅助。

## C：已登记执行证据排序

C 与 B 共用候选生成器、扫描顺序、候选池、续查机制及全部预算；对相同查询和源码，两者生成相同候选，差异限定为证据排序与解释。
主定位阶段使用同一 base 源码、固定回执包和只读检索；A/B/C 获得相同原始反馈。C 的解析与排序在本地完成，额外模型摘要或额外执行采集另行注册。
证据由运行时登记，入口绑定 receipt/tool/evaluation ID。`search_files` 只接收查询、范围和游标；编译和测试证据从成功模型响应确认的实际输入字节解析。
每条证据绑定 `evidence_id`、可见性、命令/测试 ID、退出状态、镜像/构建标识、`source_tree_sha256`、文件 SHA、`evidence_sha256` 与可见内容片段哈希。
证据哈希覆盖实际授权内容，排序特征可追溯到 Agent 可取得的字节；冷 oracle 的完整日志或仅登记为隐藏的附件保持在评测端。
编译诊断、测试断言和可用栈帧记录 `observed_location`；推导出的修复候选记录 `candidate_location`，解释保留两者关系及不确定性。
路径映射采用登记的构建根映射与 `safe_path`/`readable` 复核，拒绝绝对路径越权、`..`、符号链接逃逸和授权集合外文件；异常路径记录拒绝原因。
预注册排序优先级为当前源码匹配的直接位置证据、同文件关联证据、文本基线顺序；同级用稳定路径与位置排序，多类证据记录各自贡献。
诊断位置是症状入口，关联定义与其他文件继续保留在候选池；C 通过相同检索入口扩展，排序层仅重排共有候选。
源码树或相关文件哈希变化时，旧证据标为 `stale`，旧高权重立即失效；历史记录保留供审计，新执行回执完成哈希绑定后恢复加权。待交付回执保存产生时的源码代次；同批调用中修改并复原源码后，旧诊断继续保留原代次和过期状态。
缺少有效证据、解析失败或证据过期时 C fallback B，并记录原因；这些任务完整进入主实验分母。默认 `coverage_status=not_collected`。

## 独立实验协议

当前上下文 batch 固定为 19 个历史暴露的 fmt 开发任务、5 种上下文策略、2 次重复及 8 workers，即 `19*5*2`；定位实验使用独立 run_id、工作副本和结果目录。
定位开发集全量为 `19*3*2=114` 次运行，另有三臂各一次的 smoke。两类实验使用独立 campaign 与 attempt 身份，并共享 CPA 的 8 并发调度队列。
工作流核对固定源码 CI 与离线合同后运行 smoke；三条真实模型轨迹、用量、源码曝光及独立评分完整后自动进入全量。既有上下文实验保持原冻结协议。

| 对照 | 可识别的干预 | 共同控制 |
| --- | --- | --- |
| A/B | 原生搜索读取与“摘要 + 下钻”的界面包差异，包含工具说明、候选呈现、导航以及扫描完整性变化 | 字面匹配语义、readable、源码窗口、模型与总预算相同；记录 B 额外扫描文件数、字节、CPU 与墙钟。 |
| B/C | 共有候选上的证据排序及解释 | 候选生成与池大小、扫描额度、原始证据、窗口、执行权限、总预算相同；解释字节计入响应预算。 |
| 固定候选离线微基准 | 固定查询、源码、候选 ID、顺序及内容，仅替换序列化格式，分离格式体积和渲染开销 | 由授权材料预先生成同一候选池，分别报告生成与格式成本；结论对应固定输入上的工具行为。 |

A/B 的主要估计对象是界面包收益；聚合可能扫描更多源码，因此总成本包含新增扫描。固定候选微基准补充解释格式贡献，模型交互收益采用新的在线配对运行。
冻结任务文本、base commit、provider/模型快照、采样参数、上下文策略、工具版本、编辑与验证流程，以及 token、轮次、工具调用、墙钟预算和停止规则。
同一 `(task_id, repeat_id)` 内配对 A/B/C，按任务块随机化运行顺序、固定资源份额；模型支持 seed 时登记 seed，同时保留请求时间与实际响应。
每次运行先进入只读定位阶段，上限为 8 次工具调用或 4 次模型请求（含摘要请求），先到上限或模型给出结束说明时进入修复。阶段共享 24 次模型请求、48 次工具调用及原始总期限。排队超额调用和提前写入返回受控错误并计入调用额度。
初始公开反馈从资格归档的 baseline configure/build/CTest 三份日志提取，逐项核对哈希、任务、prepared commit 和源码身份。准备阶段仅读取当前任务允许公开的归档成员。三臂获得相同的固定反馈字节；执行原始日志与参考补丁、冷评分输出分开保存。独立评分作业从 Git bundle 恢复固定 prepared commit，并核验完整源码清单。
修复阶段反馈随各臂补丁变化，执行权限与反馈规则保持一致；新回执按当前源码重新绑定，最终补丁按统一选择规则封存。
历史 A 用于探索性重评分、字段完整性检查及固定查询工具回放；新接口引发的在线决策由新 A/B/C 实测，历史 A 保留原有条件标签。

## Gold 隔离与主指标

参考补丁、gold 路径/位置、hidden tests 与冷 oracle 输出由独立评分器持有；生成环境仅提供授权 base 源码、任务和公开反馈。
检索、排序、缓存、shell 和证据接口遵循同一隔离范围；导出源码移除携带答案的修复历史。回执包来源和哈希在任务开始前冻结。
评分器预先将参考补丁实际删除/替换行映射为 `gold_old_spans`，排除普通 diff 上下文；纯插入按预注册的旧版本邻接锚点单列评分。参考补丁存在行号偏移时，评分器在隔离 Git 索引中重放哈希核验的源码与补丁，再由实际 diff 提取旧行位置，保留原补丁哈希、重映射方式和规范化补丁哈希；原始源码保持只读。
新增文件、函数外修改及无法映射的位置保留类型、`eligible` 与原因。主表保留全部 19 个任务及其重复；冻结资格清单包含 14 个有旧行变更的任务、5 个纯插入任务。span 主指标保持每臂 28 次可评分运行的固定分母，纯插入按锚点单列。整题评分或归档缺失时仍保留其预登记资格，计为未命中和上限成本；冷验证和总成本覆盖全部运行。
gold 修改位置是参考修复位置 proxy；独立冷验证评价最终补丁，成功但 proxy 较低的替代修复进入盲审，扩展标签仅用于补充分析。

| 指标 | 统一定义 |
| --- | --- |
| changed-span 首次实际源码曝光 | 工具输出先保存为待交付回执；后续修复模型请求包含相同 call ID 与完整输出字节，并返回响应后确认曝光。按真实片段、路径、源码哈希和位置与 `gold_old_spans` 求交。 |
| 预算内命中率 | 预算内发生上述事件的运行数除以预注册的可评分运行数；主汇总按任务等权，有标签的证据缺失、失败及未命中保留在分母，标签缺失单列。 |
| candidate 曝光 | 仅路径摘要、名称、签名标签和排序解释计候选曝光；真实源码预览按统一正文规则评分。文件 Top5 按去重路径计算，作为次指标。 |
| 多位置覆盖 | 同报任一 span、全部 span、已覆盖 span 比例；纯插入锚点及无法映射标签单列。函数映射登记为 `not_collected`。 |
| 首次命中成本 | 保存确认曝光时的墙钟、承载请求轮次、工具调用及累计 provider 实际 token；批量结果按承载请求确认，重复读取继续计成本。 |

回执保留产生阶段与承载请求阶段。定位末尾的读取可由首个修复请求承载，其模型成本计入实际承载请求。预算结束后留在队列中的回执、被摘要替换的原文及无成功响应确认的输入保留交付状态；首次命中采用确认曝光记录。

未命中记录 `hit_event=false`、`first_hit=null`、`censored=true`、`observed_until` 和 `stop_reason`；标签不可评分另标 `eligible=false`，主表仍保留该任务。
每个预算轴预注册上限 τ：命中时 `capped_first_hit=min(T,τ)`，有标签且结束仍未命中时计 τ，另列实际消耗及原因；不可评分任务的 span 分数记为缺失。
主报告同时给出可评分全分母的预算内命中率、上限分数、未命中比例及标签覆盖率；仅命中轨迹的均值作为补充，提前停止与基础设施错误按原因分层。
删失曲线依据 [Kaplan-Meier 原始论文](https://doi.org/10.1080/01621459.1958.10501452)检查删失假设；主动停止、token 耗尽等相关删失以全分母和上限分数为主要口径。

## 成本、冷验证与判定

provider 回执记录输入、输出、缓存读写和可用推理 token，保留实际费用与价格日期；字段缺失明确标记，字节指标单独报告。
墙钟分解为扫描、聚合、排序、模型等待、定位、构建测试及冷验证；记录响应字节、唯一源码行、重复读取与预计算冷启动/摊销成本。
每次封存补丁使用独立 `(task, arm, repeat, patch_hash)` 评价 ID，从固定 base 和依赖镜像创建干净环境，重新配置、构建并运行隐藏缺陷测试及回归测试。
冷验证输出在整批生成结束后由隔离端发布；统一登记 `apply_failed`、`build_failed`、`test_failed`、`resolved`、`infra_error`、`flaky` 与重试规则。流程参考 [SWE-bench Evaluation Guide](https://www.swebench.com/SWE-bench/guides/evaluation/)。
按任务先汇总两次重复，再计算 B-A、C-B 的配对差值；报告胜/平/负与按任务整体重采样的区间，重采样保留所有臂和重复。统计单位参考 [Demšar，JMLR 2006](https://www.jmlr.org/papers/v7/demsar06a.html)。
判定同时考察 changed-span 命中、上限首次命中分数、provider 真实 token、端到端墙钟及冷验证；接受阈值与质量容忍度随协议预先冻结，smoke 核验接线、计量和评分完整性。
19 题均属于历史暴露开发集，结论首先描述该集合；共享缺陷来源另作分组分析，跨仓库收益由后续独立任务验证。

## 可选高投入扩展与验收

逐测试 `llvm-cov + Ochiai` 单列为高投入扩展，默认方案复用现有构建、测试与可用栈回执，框架和覆盖插桩保持可选。
覆盖链路包括 `-fprofile-instr-generate -fcoverage-mapping`、逐测试 profile 隔离、`llvm-profdata merge`、`llvm-cov export` 及通过/失败标签；参见 [Clang 官方流程](https://clang.llvm.org/docs/SourceBasedCodeCoverage.html#the-code-coverage-workflow)与 [llvm-cov](https://llvm.org/docs/CommandGuide/llvm-cov.html)。
以逐测试二值命中计算 `Ochiai(s)=ef(s)/sqrt(F*(ef(s)+ep(s)))`，零分母记零；公式主来源为 [PRDC 2006，第 3 节式 (4)](https://webarchive.di.uminho.pt/haslab.uminho.pt/ruimaranhao/files/azg_prdc06.pdf)。
该扩展需另计插桩构建、测试隔离、profile 处理与存储成本，明确模板/宏实例聚合、部分覆盖、崩溃缺测和异常路径误差，并保持相同可见测试与重试预算。
离线验收覆盖截断前聚合、下界计数、续查完整性、64 KiB 限额、既有窗口、路径越权、证据哈希篡改、源码失效、fallback、纯插入标签及未命中计分。
smoke 验收覆盖原生与摘要下钻的完整交互、B/C 固定输入候选一致、实际 token 回执、源码曝光时间线和独立冷验证；输出保留协议哈希、逐运行明细、失败分类与任务配对表。
默认策略的选择同时要求任务等权冷验证成功率保持、上限首次命中调用数下降及实际输入 token 持平或下降。独立全量开发实验提供选择依据，全部原始轨迹和负向结果保留。
