状态：**已完成**。产品版本：**0.2.0.dev3**。任务格式：**v2**。

## 独占资源

每个 Run 新建 0700 控制目录和独立工作区；已有目录拒绝占用。
运行全程持有 `.run.lock` 的独占文件锁，以打开的描述符维持，不以文件是否存在判断锁状态。
任务、事件、清单、日志与报告使用 0600。`resources.json` 记录 Run ID、UID、源仓库、commit、
控制目录与工作区身份、锁路径、实际 Git common/manager、工作树和容器的创建及清理状态。

Git 工作树保存根、manager、common 的身份和双向指针摘要；清理前复核身份与登记路径。
容器记录不可混淆的名称、完整 ID、Run/操作/用途标签和镜像 ID。
创建后先保存实际身份，再启动；清理依据已记录 ID，不按相似名称批量删除，也不运行全局 prune。
ID、名称或标签不符时拒绝删除该对象，记录无法确认清理。

## 固定执行配置

容器使用非 root 65534:65534、断网、只读根文件系统和 `/src`、无 capabilities、
no-new-privileges、init、有限 nofile/core、无 host PID/IPC 或设备。
固定入口为 `/usr/bin/sleep infinity`，禁用镜像健康检查和重启；额外镜像 VOLUME 在创建前拒绝。
创建后 inspect 实际权限、挂载、镜像及 Task 的 CPU、内存、PID、tmpfs 数值；
daemon 不支持要求的 cgroup 限额时拒绝运行。

`/build` 为 Task 限额 tmpfs，UID/GID 65534、0700、nosuid/nodev，允许执行编译产物；
`/tmp` 为 64 MiB tmpfs。固定 HOME/TMPDIR、locale、CMake/CTest 并行设置，不继承宿主环境。
每次评估检查镜像中的基本工具，记录路径及 CMake/CTest 版本，最低要求为 3.26。
同次评估的配置、编译和测试共用 `/build`；下一次评估使用新容器和空构建区。

## 命令证据与预算

每条容器命令使用独立 command ID，持续读取 stdout/stderr，直接保存两份原始文件：

```text
logs/<command-id>/stdout.bin
logs/<command-id>/stderr.bin
```

两个 EvidenceRef 固定 Run 内相对路径、大小与 SHA-256。正常无输出也保存零字节文件；
日志创建失败时引用可为 null，并以基础设施错误结束，不能将缺失日志视为空输出。

两流累计观察字节数 **达到 4 MiB** 即停止命令并销毁整个容器，状态为 `output_limit`；
恰好达到上限也按证据不完整处理。最多保存 4 MiB，不等待原进程自然结束后才截断。
模型预览合计最多 64 KiB，分别保留首尾、标记省略、以 UTF-8 replacement 解码并转义控制字符。
预览省略不意味着原始日志不完整；失败签名在完整原始 stdout 或 stderr 内查找，不跨流拼接。

每 Run 的非源码审计文件上限 **256 MiB**，覆盖原始日志、事件、清单、补丁、资源记录和报告；
预留最终收尾空间，并在写入和启动命令前检查预算与可用磁盘空间。
完整补丁与 manifest 不接受截断；预算耗尽时停止新增执行，保留已有证据和最终错误诊断。
大报告可以省略派生预览或详细列表，并指向仍完整保留的事件、资源文件；不删除早期证据腾出额度。
源码工作树及最多保留的一份诊断快照受源码大小边界约束，位于独立工作区，不纳入非源码审计预算。

## 终止与清理

底层状态区分 `exited`、`timed_out`、`oom_killed`、`cancelled`、`infra_error`、`output_limit`。
正常非零退出仍为 `exited`；仅凭 137 不推断 OOM，须有 Docker 的 OOM 状态证据。
命令超时、取消、输出超限或执行状态不确定时，停止安排本次评估的后续命令。

停止时先清理整个容器，再回收宿主 Docker 客户端进程组；每次清理尝试共享十秒预算。
删除后再次 inspect，只有明确不存在才确认成功；daemon 失联、返回损坏或容器仍存在均不算成功。
中间命令的 `cleanup_confirmed=false` 表示当时容器仍用于同次评估，结束事件提供最终清理证明。
原始失败与 cleanup_error 分别保留；任何无法确认的容器清理都阻止最终通过。

## 快照与保留

源码快照位于 `workspace.root/<run-id>/snapshots/`，按评估独立创建，并记录根身份和源码摘要。
普通成功诊断结束即释放其快照；其它评估最多保留最近需要诊断的一份。
收尾报告落盘后，按以下策略处理所属工作区，再保存最终结局与清理状态：

| retain | 工作区结果 |
| --- | --- |
| none | 移除 repair、validation 工作树及源码快照。 |
| on_failure | 通过后移除；其它结局保留 repair 与最近诊断快照。 |
| always | 保留 repair 与最近快照；validation 工作树仍移除。 |

所有模式均保留审计产物，不保留活跃容器。容器删除未确认时保留相关工作区供诊断；
身份变化或清理失败会记录错误，不递归追踪未知链接、不声称已删除。
跨 Run 历史审计文件由操作者管理；当前没有自动接管崩溃资源或恢复执行的能力。
