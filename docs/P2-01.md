P2-01 验收版本：**0.3.0.dev1，Task v2**。三表与外层事务已完成；Checkpoint 与暂停见 [P2-02](P2-02.md)。
权威约束见 [状态与安全恢复](../specs/2026-10-19.2/docs/STATE_AND_RECOVERY.md)。

## 权威状态

新 Run 的 events.sqlite3 使用 user_version=2，且只有 runs/events/checkpoints 三表。
runs 记录单个 Run 的状态、结局、冻结输入引用、绝对期限、累计 steps_used、tool_calls_admitted、
实际用量聚合和 segment_open。checkpoints 当前为空，不提供恢复效力。
不保存 SDK 会话数据库、逐工具调度行或重做指令；原生 Items 仍由公开 SDK 管理。

RunResources 的 flock 覆盖整个运行及最终导出，EventLog 借用同一锁；独立写连接也必须先取得同 Run 的锁。
数据库采用 DELETE journal、FULL synchronous、foreign_keys=ON。JSON 在入库边界校验，缺失 token 保持 null。
阶段、入口、结局及冻结输入有明确约束；verify-patch 的模型步骤和工具计数保持零。

## 提交边界

| 边界 | 同一事务中的事实 | 提交后的动作 |
| --- | --- | --- |
| 创建 | runs 初始行与 run_created，保留原始 created_at/deadline_at | 准备输入 |
| 准备完成 | 实际冻结身份、inputs_json、inputs_frozen 与进入 REPRODUCING 的事件 | 执行基线 |
| on_llm_start | model_started、累计 steps_used、未知用量与 segment_open=1 | 发出模型请求 |
| on_llm_end | model_finished 与已观察累计用量 | 协议校验及工具预算准入 |
| 整批准入 | tool_batch_admitted 与累计 tool_calls_admitted | SDK 串行分派本批工具 |
| 终结 | FINISHED、outcome/reason_code 与引用最终事实的事件 | 导出 JSONL/报告 |

事务失败不允许模型请求或工具批次继续；已提交的计数不退款。
执行阶段入口校验冻结文件引用和实际身份，预算上限来自冻结 Task；期限不重新计算。
模型响应、工具结果或正常最终文本不会关闭 segment_open。
只有后续任务实现的安全输入 Checkpoint 才能在修复阶段关闭片段；当前不能从完整工具日志推断恢复资格。
终态和 VERIFYING 的片段值也不提供继续执行资格。

## 崩溃与查询

真实子进程在事务提交前和提交后分别强制退出，验证状态、事件、步骤和片段一起回滚或一起保留。
测试强制 SQLite 缓存溢出以覆盖原生回滚日志；持锁写连接只打开已有数据库，由 SQLite 处理未完成事务。
这是数据库一致性检查，不是模型或工具重执行。
[SQLite 回滚日志协议](https://www.sqlite.org/lockingv3.html#hot_journals) 定义原生恢复顺序。
只读 inspect 不执行回滚写操作；需要回滚的文件或其它不可读状态明确报错，不创建新库。

inspect 从一致性快照读取 runs，并核对事件前缀；最终报告的计数、用量和期限必须与权威行一致。
数据库损坏、未知版本、链接、身份变化或状态与事件不符均拒绝；磁盘上的 report.json 不能替代数据库。
database_version=2 与 event_format=1 分别表示数据库版本及原有事件信封版本。
schema 0/1 历史审计保持原版可读，不能以补建表的方式升级为可恢复 Run。
终态之后的写入拒绝；报告删除、重建和导出失败不会改写既有结局。
