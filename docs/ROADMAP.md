## 下一轮实验

| 工作 | 验收标准 |
| --- | --- |
| 新实例资格与冻结协议 | 3 道本项目中尚无模型修复尝试的 C++ 缺陷；基线复现、参考补丁和统一外部 Oracle 通过，源码与配置固定 |
| 三框架首跑 | Full、mini、Codex 每题各一次，共 9 次；保存全部候选、失败、用量和独立评分 |
| 中途自检消融 | 同题增加关闭中途执行与测试反馈的 Full，各一次；与上述 Full 首跑配对，共增加 3 次 |

三道题合计 12 次运行，按每次最多 12 请求计为 144 次正式请求；供应商 `max` 校准单独记账。
配对记录外部 Oracle 结果、模型请求与真实 Token、自检次数和阶段耗时。
Full 两组使用同一基线输入、相同请求与时间预算，并各自完成内部独立验收和外部 Oracle。
三框架计时分别列出准备、基线、修复、内部验收与外部 Oracle。

已有能力保留：只读接口追踪、可编辑状态反馈、剩余预算反馈、紧凑诊断和独立验收。
后续工作复用现有执行器和任务适配方式；符号导航扩张、自动源码片段注入、并行工具候选、
通用 Harbor 和复杂恢复扩展继续封存。

新实验使用独立协议、源码身份和预算，供应商响应中的 `max` 校准通过后进入正式运行。
v2 配置与成绩完整保留，全部历史模型用量见[原始账本审计](../benchmarks/model-usage-audit.json)。
