# 上下文优化的论文依据与负载设计

代码修复场景已有累计输入 Token 降低的直接研究证据。ReproPatch 优先核对自身轨迹中的压缩机会，再选择干预时机和后续负载。任务成功率、累计输入、辅助调用、运行时间和原文恢复成本共同决定策略取舍。

## 最接近的论文

| 研究 | 实际负载与方法 | 可直接引用的观察 |
| --- | --- | --- |
| [AgentDiet，FSE 2026](https://arxiv.org/html/2509.23586v2) | Trae Agent；Verified 200 题和 Multi-SWE-bench Flash 300 题。Flash 步数上限 100；延迟两步处理超过 500 Token 的历史步骤，删除无用、重复和过期内容 | Flash 的 40 道 C++ 题：Claude 4 Sonnet 主 Agent 累计输入下降 39.8%，成功题数持平；Gemini 2.5 Pro 下降 70.2%，少成功 1 题。辅助反思成本另列 |
| [The Complexity Trap，NeurIPS 2025 DL4Code](https://arxiv.org/abs/2508.21433v3) | SWE-agent，Verified 500 题，保留最近 10 轮观察，旧观察替换成占位符 | Qwen3-Coder 的每题成本 $1.29→$0.61，成功 267/500→274/500；Gemini thinking 的成功 202/500→182/500。窗口效果随框架和模型变化 |
| [ACON，ICML 2026](https://arxiv.org/abs/2510.00615v3) | AppWorld 168 题；历史阈值 4096、观察阈值 1024 Token；按任务调整压缩指南 | GPT-4.1 基线平均每题峰值 9.93K，历史压缩为 7.33K；任务完成率 56.0%→56.5%。峰值排除系统提示，累计输入另行核算 |
| [TACO，2026 预印本](https://arxiv.org/abs/2604.19572v3) | 构建、测试等终端输出的结构化规则压缩，含辅助规则选择与更新 | Mini-SWE-Agent / SWE-bench Lite 表列总 Token 307.61M→270.53M，五次运行成功率 56.30±2.32%→57.12±2.19%。具体诊断解析器仍需自身消融 |

AgentDiet 的分析轨迹平均约 40 步、48.4K 轨迹 Token，其中工具输出约 30.4K，逐轮重读形成约 1.0M 累计输入。ReproPatch 当前 fmt 合同每条上限为 24 次模型请求，历史压缩水位为 48,000 估计输入 Token，工具输出已有归档折叠。这些差异决定了压缩机会和触发后可获益的轮数。

当前精确去重要求相同参数、源码身份和回执内容。AgentDiet 的冗余还覆盖编辑内容重叠、定位结束后的旧候选以及大量通过测试明细。对这些信息采用可核验的局部裁剪和状态替代，需要保留命令、退出码、源码版本、最新失败、待验证项及完整原文入口。

## 压缩机会分析

已完成五组批次的 190 条轨迹完整纳入分析，baseline 的 38 条作为自然负载参照。3,584 次模型请求共使用 52,842,882 输入 Token，供应方响应、SQLite 账本和公开结果逐条核对一致。

| baseline 负载指标 | 结果 |
| --- | ---: |
| 轨迹数 | 38 |
| 每条模型请求中位数 | 19 |
| 每条峰值供应方输入 Token 的中位数 | 22,232 |
| 达到运行时 48K 压缩水位 | 0/38 |
| 出现超过 500 文本 Token、延后两步仍被重读的回执 | 38/38 |
| 满足上述条件的回执 | 251 |
| 其中 `read_file` 回执 | 207 |
| 候选回执在后续输入中的重读次数中位数 | 8 |

全批两次通用历史压缩后均剩余零次修复请求，其中一次启用了状态附加机制。该状态案例将运行时估计输入从 48,182 降至 17,045 Token，24 次请求由 23 次修复与 1 次压缩组成。提前处理已被多次读取的文件回执，是后续实验的首要干预方向。

候选长度提供筛选条件，信息价值由逐行重叠、明确的源码变更、最新失败与后续查询判断。分析分别保留以下量：

- 模型请求、工具调用、预算耗尽状态，以及每次请求的供应方用量。
- 原始输出、实际可见回执、输入峰值；字节、文本 Token 估计和供应方账单分别列示。
- 各机制的候选、触发、跳过原因、净省略量和触发后的剩余请求。
- 每段较早工具输出被后续输入再次携带的次数及其固定轨迹投影潜力。
- 输出内重复、跨调用重复、构建与测试进度，以及具有替代证据的旧文件／旧验证结果。

历史阈值候选为 4096、8192、16000、24000、32000、48000；单轮候选采用 500 Token 代理阈值和延迟两步。运行时阈值按原实现估计复算，文本 Token 估计注明编码器。在线实验计入主模型、压缩器、摘要器和恢复原文的全部模型调用。

207 个 `read_file` 候选中，29 个与后续同版本读取存在逐行重叠，40 个包含后续成功编辑的完整旧文本锚点，二者交集为 8，合计 61 个。其余 146 个占文件候选后续携带量的 64.3%，选择性提取需要保留这些内容中的有效代码证据，并通过独立在线运行评估。

完整任务集合提供主要效果表。实际触发子组用于解释机制；需要比较有压缩机会的任务时，采用实验前固定的 baseline 条件对所有组取相同名单。失败、重试和零候选任务均进入分母。

## 效果评价

上下文方向关注整任务累计输入、独立冷评分、运行开销和信息恢复成本。检查点方向测量从头重跑与实际续跑的请求、Token 和时间差。独立验证方向统计同一最终补丁的探索测试通过与冷评分失败，并单列额外测试覆盖、构建残留和评分完整性问题。

完整任务、逐题失败、原始数据与源码身份共同组成结果包。提前压缩的在线累计 Token 收益由新冻结的配对实验计量，历史机会分析用于解释候选覆盖与触发时机。
