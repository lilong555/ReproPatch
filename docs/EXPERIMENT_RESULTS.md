# Agent 运行时实验结果

实验覆盖模型轨迹配对、上下文策略与故障定位，以及长输出归档、暂停恢复、独立补丁验证、构建复用和结构化检索缓存。
运行时微基准及结构检索使用固定公开源码 `9cf01099206131ba6f984661a97f7aa65ee8b68a`，模型调用为零；
回执投影保存独立的逐文件实现哈希。历史真实模型结果保留各自的执行版本和任务身份。

## 完整模型实验

| 实验 | 样本 | 观测结果 | 完整材料 |
| --- | --- | --- | --- |
| 五组上下文策略 | 19 题 × 5 组 × 2 次，190 条 | baseline / diagnostics / dedup / state / combined 分别通过 34 / 31 / 33 / 32 / 30 条，每组 38 条；诊断与去重零触发，状态压缩一次 | [分组用量、逐题失败与原始轨迹](../benchmarks/context-ablation/full/README.md) |
| 定位 A/B/C | 19 题 × 3 组 × 2 次，114 条 | native / bounded / feedback 分别通过 32 / 33 / 30 条，每组 38 条；B、C 平均输入 Token 比 A 增加 16.8% / 20.5%，默认保持 A | [定位、用量、配对差异与原始轨迹](../benchmarks/localization-ablation/full/README.md) |
| 回执上下文策略预检 | 1 题 × 5 组，5 条 | 诊断提取实际触发 2 次，29,340 → 10,064 字节；诊断组通过冷评分，其余组失败 | [实际触发、跳过原因与原始轨迹](../benchmarks/context-ablation/trigger-smoke/README.md) |

各批次均使用 `gpt-6-luna`、`max` 推理档位和固定预算。完整实验使用此前已接触的 fmt 开发任务；上下文与定位分别保存独立协议、源码和原始结果。定位主指标采用预登记的 14 个 changed-span 任务，纯插入的 5 个任务单列锚点指标，冷评分与 Token 使用全部 19 题。

## 主要结果

| 实验 | 样本与结果 | 计量 |
| --- | --- | --- |
| 历史轨迹复算 | 19 道 fmt 题、五种配置、95 条所选轨迹；86/95 冷评分通过，95/95 用量账本闭合 | 历史真实模型，1,764 次请求 |
| 长输出离线投影 | 六份原文来自五条轨迹，174,602 → 147,456 字节，减少 15.55%；原文回读与调用配对全部成立 | UTF-8 字节 |
| 暂停恢复 | 三次有效计时，中位 0.530 秒，范围 0.468–2.479 秒；同 Run、源码、下一输入、累计预算和截止时间一致 | ScriptedModel 与真实 Docker |
| 独立补丁验证 | 正常修复接受；测试篡改在保护路径阶段拒绝；引入回归的修复由 P2P 拒绝，各一次 | 真实 C++ fixture 与 Docker |
| 构建复用 | 固定 fmt 目标、相同源码，冷构建与热 ccache 新构建目录各三次，中位 13.268 → 0.868 秒 | 历史构建微基准 |
| 结构化检索 | 12 个预登记目标，文本搜索覆盖 12/12、语法索引覆盖 11/12；返回体积 6,419 / 42,518 字节 | 同三份真实 fmt 头文件 |
| 索引缓存 | 五组初次索引与缓存查询，中位 14.132 → 0.517 ms；单文件改动触发单文件重解析 | 本地读取、哈希、索引与查询 |
| 结构化诊断回放 | 四归档、89 条回执；四次诊断触发，合计返回 239,884 → 205,505 字节；精确去重候选为 0 | 固定历史回执、离线 UTF-8 字节 |

恢复实验另有首批三次观察器错误，原始记录独立保留，累计登记六个 Run。有效计时采用修正
观察器后新登记的三个样本。三个补丁场景合计产生另外三个 Run，全部九个 Run 的完整状态可审计。

历史 95 条轨迹属于五个历史源码版本，任务为已曝光的开发/配置复核题。五种配置同时涉及工具、
提示或执行方式差异，结果按配置组合比较。候选构建失败、候选测试失败与执行停止原因分别列示。

结构化检索的返回对象包含定义位置、源码哈希和语法关系，载荷更大。缺失的类目标位于含宏的头文件
区域，解析记录出现 `parse_has_error`。缓存结果体现相同源码重复查询的性能，包含读取和重新哈希。
长输出实验记录离线字节变化；模型 Token 使用历史供应方用量字段计量。

## 离线复算

在安装了项目 `agent` 依赖的 Python 3.12 环境中，使用新输出目录：

```bash
python scripts/benchmark_runtime_evidence.py audit \
  --package benchmarks/runtime-evidence-20261106/public-inputs \
  --output /tmp/repropatch-runtime-audit

python scripts/benchmark_code_index.py \
  --replay benchmarks/code-index-20261106 \
  --output /tmp/repropatch-index-replay
```

首条命令核对 95 份账本、六份长输出及九个 Run 的原始状态；第二条命令从已归档源码重新执行
查询、缓存和失效测量。源码与原始结果保持只读，派生结果写入指定目录。
