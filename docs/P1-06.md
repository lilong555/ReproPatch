# P1-06：共享独立验证器与外部补丁验收

状态：**已完成**。产品版本：**0.2.0.dev4**。Task 格式：**v2**。
自动路径 SDK 契约见 [P1-05](P1-05.md)。

## 两条入口

`run` 在原始基线合格后执行受控自动修复，再交接冻结候选；
`verify-patch` 先复制并静态审核外部 patch，再执行同一原始基线和最终独立验收。
两条路径共用 `evaluate_checks`、`verify_candidate`、CandidatePatch 和资源生命周期。
外部路径不导入 models、Agents SDK 或 OpenAI SDK，不读取模型密钥、不创建 Agent。

```bash
repropatch verify-patch examples/tasks/negative-maximum.v2.yaml \
  --patch examples/patches/negative-maximum.correct.patch --producer local --json
```

参数为必需的 `TASK`、`--patch FILE`，以及可选的 `--producer NAME`、`--producer-trace FILE`、
`--output-root DIR`、`--json`。不接受 engine、model、key、paid 或 pause 参数。
Run ID 为 32 位小写 UUID。JSON summary 只有一条最终记录，包含实际 input_mode、outcome、reason_code 和产物目录。

## 外部输入与候选

patch 最多 8 MiB，trace 最多 16 MiB；只接受完整、稳定、单链接普通文件，拒绝 symlink、FIFO、目录和超限输入。
输入按原始 bytes 复制为 `producer/input.patch` 与可选的 `producer/trace.bin`，分别保存 EvidenceRef。
后续使用保存的副本，不重新读取原输入，也不解析 trace 的命令、成功、token 或费用声明。
producer 只是操作者提供的来源标签；trace_trust 为 external-untrusted，生成用量和费用保持未知。

新 candidate 工作树从固定 base 创建，与 baseline 的初始完整 SourceManifest 相同。
使用 Git 原生 numstat/summary、apply --check 和普通 apply；仅已有 editable C/C++ 文本内容变化可进入候选。
空补丁、非法格式、越界、二进制、mode、创建/删除/重命名或无法应用的输入可在执行容器创建前拒绝。
规范 patch 的表示可以与外部输入不同，但实际源码效果必须与冻结 manifest 完全相同。
最终仍从原始 commit 在另一棵新工作树应用规范 patch，核对完整清单和再次导出的规范 diff。

## 结构化基线

每次评估在全新容器与空 /build 中串行执行：

1. 固定 configure 与 build。
2. `ctest --test-dir /build --show-only=json-v1`，保存原始 JSON。
3. 按 Task 顺序逐项 F2P，再逐项 P2P；每项使用精确转义 selector、独立 UUID JUnit 路径及阶段剩余 timeout。
4. 在销毁容器前有界读取 JUnit 原始 bytes，保存 EvidenceRef，再确认容器删除。

选定测试身份包括 name、完整 command argv、全部 properties；属性按名字排序，保留值类型和列表顺序。
backtrace 不是执行身份。重复或缺失的选定名字、不支持的自动 fixture/DEPENDS、未知发现协议均不能产生通过。
原始 inventory 不重序列化覆盖；独立验证的选定身份必须与 baseline 逐项相同。

F2P 必须真实运行并普通失败，CTest 退出码等于声明值，完整原始 stdout 或 stderr 中出现字面失败签名。
不跨流拼接，也不从 preview 或 JUnit 文本猜测签名。原始 P2P 必须逐项实际通过。
基线 P2P 回归或证据不完整优先于 F2P 不匹配，不能因列表顺序改变而误进入修复。

## JUnit 与观察

解析依据固定镜像中实际 CTest 3.28.3 的 [原始样本](evidence/p1-06/ctest-samples/manifest.json)。
样本覆盖通过、普通失败、skip、disabled、timeout、崩溃和 WILL_FAIL；命令、版本、镜像及原始双流一并保留。
协议参考 [CTest 手册](https://cmake.org/cmake/help/v3.28/manual/ctest.1.html) 与
[固定版本状态实现](https://github.com/Kitware/CMake/blob/v3.28.3/Source/CTest/cmCTestTestHandler.cxx)。

JUnit 必须恰好一项结果、名字和计数一致、状态与退出码相符。未知状态、错误编码、DTD/实体、异常深度、
嵌套状态、错误计数、空文件、缺失 XML 或读取失败不能解释为“没有失败”。
TestObservation 区分 passed、failed、skipped、not_run、timed_out、crashed、invalid。
每个计划名字都有观察；未启动的测试保留 null command/result/exit code 和明确诊断，不构造退出 0。

## 独立结论

| 观察 | Outcome |
| --- | --- |
| 合格原始基线、合法候选、字节往返一致、身份一致、所有测试实际通过且清理确认 | ACCEPTED |
| 候选越界、普通构建/测试回归、可靠测试崩溃、身份变化、必需测试缺失/skip/disabled | REJECTED |
| 原始 F2P 通过或正常失败但签名/退出码不匹配，其余基线完整 | NOT_REPRODUCED |
| 基线 P2P 回归、未完成观察、timeout/OOM/输出超限、未知执行或缺失/畸形证据 | INCONCLUSIVE |
| 宿主控制面、输入读取、源码不变量、保存证据损坏或原始构建错误 | ERROR |
| 操作者取消 | CANCELLED |

已经可靠确定的候选回归不会被随后其它用例的证据中断洗成通过或不确定。
清理未确认阻止 ACCEPTED，禁止继续 Agent 调用；已知 REJECTED 可以保留自身结论并另记 cleanup_error。
自动路径的步骤预算停止仍可在验证余量内交接合法候选，不把 Agent 自检或最终声明当作 independent。

验证执行使用 Task wall、verification reserve、命令上限与最后十秒清理余量。
预留不足以启动必需验证时返回 INCONCLUSIVE，不跳过 P2P、不采用旧自检结果补齐。
CLI 退出码：ACCEPTED 为 0；REJECTED/NOT_REPRODUCED/BUDGET_EXHAUSTED 为 1；静态输入错误为 2；
ERROR/INCONCLUSIVE 或读取/导出失败为 3；用户取消为 130。

## 最小报告与支持范围

report.json 包含 input_mode、FINISHED、outcome/reason、实际来源指纹、task 引用、timing、engine/agent/producer、
usage/cost、候选、完整 baseline/independent、清理结果和 limitations。
EvaluationEvidence 保存固定阶段、inventory、identities、全部计划测试、实际命令与最终清理证明；
每次评估另以私有 JSON EvidenceRef 保存。报告保留少量兼容字段，真实观察均来自同一验证器。

verify-patch 的 engine 为 none，Agent 计数和 HTTP attempts 为零，token 用量与 cost 为 null。
自动入口使用公开 SDK 与六工具；原生上下文、整批预算和取消边界见 [P1-05](P1-05.md)。
events.jsonl 由 SQLite 导出，report.trace 引用领域事件；inspect/report 契约见 [P1-07](P1-07.md)。
当前不提供 Checkpoint、Resume、Replay 或 Harbor，不估算模型修复率。

[测试报告](TEST_REPORT.md) 提供 **238 项普通测试、15 项真实 Docker 测试**及干净核心 wheel 安装证据。
固定 oracle 和只读测试不能证明任意恶意源码对所有输入正确；Docker 仍共享宿主内核。
