# SDK 自动修复契约

当前版本：**0.2.0rc1，Task v2**。自动路径与纯验证路径共用基线、源码字节清单、资源所有权和独立验证器。

## 入口与所有权

`run TASK --engine fake --mock-script FILE` 使用公开 `agents.testing.ScriptedModel`。
脚本为 [P1-04 定义的原生 JSON](P1-04.md)，耗尽仍请求会报错，不自动补结束文本。
`run TASK --engine agents-sdk --model MODEL --allow-paid-model` 使用 AsyncOpenAI/OpenAIResponsesModel；
可指定受审核的 HTTPS `--api-base` 和环境变量名 `--key-env`，凭据不放入 Task、argv、上下文或报告。
真实模型配置在创建 Run 前校验，客户端只在合格基线后的 Agent 阶段构造，退出时关闭。
当前没有经 V-LIVE 认证的实际模型/端点组合，不自动退回 Chat Completions。
默认引擎为 fake；真实引擎也接受 `sdk` 别名，模型名也接受 `--model-name`。

`verify-patch` 只需核心 PyYAML；其导入链不加载 models、Agents/OpenAI SDK，也不读取模型 key。
自动入口需要 `agent` extra。固定依赖、官方接口与安装方式见 [SDK 基础契约](P1-04.md)。

`run_agent` 构造领域 hooks 与六工具，调用一次 `run_sdk`，由公开 Runner 管理循环和 Items 关联。
返回冻结的 AgentResult；错误以领域/SDK异常终止。没有自有 Model/Turn、四角色对话表、HTTP 协议、worker、JSON RPC、
上下文裁剪器、Session、handoff、MCP、hosted tools、服务端 conversation 或自动 previous_response_id。

## 六个工具

| 工具 | 参数 | 边界 |
| --- | --- | --- |
| list_directory | path="." | 只列 frozen readable 的直接子项，最多 200 项、64 KiB |
| read_file | path, start_line=1, max_lines=200 | UTF-8，最多 400 行、64 KiB，包含实际行范围和截断标识 |
| search_code | query, path="." | 大小写敏感字面搜索，query 最多 1 KiB，最多 100 匹配、64 KiB |
| edit_file | path, old, new | 已有 editable C/C++，唯一精确匹配；原子写入保持字节与权限，返回前后 SHA-256 |
| run_command | name=reproduce/verify | 新容器内固定配置/编译/F2P 或 F2P+P2P，自查不替代最终验收 |
| run_shell | command, cwd="/src", timeout_seconds=null | 最多 16 KiB，cwd 仅 /src 或 /build；新 Docker 容器内 /bin/sh -lc |

六个回调均由宿主静态声明为真正 async；SDK 根据类型注解生成 schema，不维护另一份 JSON schema。
SDK schema/参数解析错误按协议错误终止。已准入的政策错误返回
`{"ok":false,"error":{"code":"PATH_NOT_EDITABLE","message":"..."}}`；成功返回 `{"ok":true,"data":...}`。
工具输出显式编码为 JSON 文本交给 SDK，不使用 Python dict 的 repr。
仅 PolicyError 被作为可纠正结果捕获；磁盘、Git、Docker、证据或事件错误传播，不伪装成空搜索或普通测试失败。

run_shell 的源码快照、完整 manifest、命令原始 stdout/stderr 和删除确认都有所属记录。
容器断网、非 root、源码及根文件系统只读，/build 为有限 tmpfs；没有宿主 Shell、PTY 或持久终端。
cd/export、构建产物和后台派生进程不跨调用保留。所有源文件修改只经 edit_file。

## 准入与时间

1. 请求前的公开 input filter 检查 Agent 阶段期限、剩余步骤、上一工具清理和 instructions+原生输入的 256 KiB 限额。
2. on_llm_start 持久化开始事件并消耗一个 turn，失败不退款；不是 HTTP 次数。
3. on_llm_end 保存最多 1 MiB 的原生输出、raw_usage 与引用，再检查执行项、未完成标识、每响应非空唯一 call_id、最多八个调用和静态工具名。
4. 工具总数超过余额时整批拒绝，一项也不执行；准入后一次性扣额度，参数错误或中途失败不退款。
5. SDK 串行执行。下一请求前必须确认所有所属容器删除；不伪造未执行的工具结果。

max_steps 只阻止下一模型请求，最后一个允许 turn 中的合法工具仍执行。
模型输出 token 上限、模型 timeout、SDK/客户端零重试、远程 store/tracing 关闭均显式设置。
Agent 截止时间保留 Task 的 verification reserve 与最后十秒清理余量；工具内 Git 和每条容器命令也受阶段期限限制。

## 原生附件与用量

原生输入与输出保存在 0700 的 `agent/native/`，文件为 0600，受 Run 的 256 MiB 审计预算约束。
领域事件只写 EvidenceRef、step、身份及用量；reasoning/encrypted_content 不解码，也不写进领域日志或报告正文。
SDK 将 reasoning、function_call 和 function_call_output 传入后续请求，保留不透明 continuation 与 call_id。
不手动删除旧轮，不另请模型摘要，不自动换模型。

用量仅按公开 raw_usage 字段存在性提取。缺失值为 null，显式零保留零；
known_tokens 分别累积已知部分，unknown_turns 记录缺失用量或已开始但未返回的 turn 数。
fake 的合成标识为 true、HTTP 次数为 0；实际适配器未观测底层次数时为 null，不用 turn 数冒充 HTTP 次数。
engine.kind 区分 fake、agents-sdk、none；versions 只记录实际加载的包，外部生成费用和成本保持未知。

## 结束与取消

| Agent 停止 | 候选处理 |
| --- | --- |
| MODEL_FINISHED | 合法非空补丁独立验收；无补丁 REJECTED/NO_PATCH |
| STEP_BUDGET、TOOL_BUDGET、CONTEXT_LIMIT、AGENT_DEADLINE | 合法补丁仍可独立验收；无补丁 BUDGET_EXHAUSTED |
| MODEL_ERROR、PROTOCOL_ERROR | ERROR；保存未验补丁，不继续模型或独立验收 |
| USER_CANCELLED | CANCELLED；清理，不在取消后继续验收 |

HTTP 授权、限流、服务端、连接、请求超时和服务端上下文错误使用安全的不同 reason_code，不附供应商响应体或 request_id。
SDK 公开 UserError 的领域异常通过公开异常链传播；不读取 SDK 私有状态。

同步文件/Git/容器 helper 在 async 工具内串行执行，自身具有有限执行与清理边界；没有 to_thread 写入。
它们执行期间不会接受新的异步工具，取消延迟受当前同步操作边界约束，不承诺即时中断文件系统 I/O。
SDK 返回时仍可能存在收尾任务；领域入口闭锁阻止后续工具，Run 外层拥有资源清理并核验容器删除。
模型客户端、工具内部 finally 或“本地 await 已取消”都不能代替所属资源的停止证明。

验收覆盖与原始证据见 [测试报告](TEST_REPORT.md)。领域事件仅写 SQLite，权威导出与查询见 [P1-07](P1-07.md)。
