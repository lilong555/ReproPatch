# 项目实验结论 · 2026-11-07

提前上下文压缩取得先导正向结果：在六道 fmt 任务的 36 条三组轨迹中，`early_state` 平均输入降低 **21.98%**，冷验收与基线均为 **10/12**，全部辅助调用已计入。检查点恢复的状态一致性和准入速度得到验证，故障后总输入增加 **29.06%**。政策有效期过滤、业务写入对账和任务账本有明确的定向正结果；偏好记忆呈现交互减少与严格文本成功率下降的共同表现。

## ReproPatch：上下文优化

`early_state` 两次重复的全体任务输入分别降低 22.51% 和 21.42%。按任务均值，`fmt-3750` 降低 49.73%，`fmt-3819` 降低 43.51%；其余四题增加 0.49%–44.81%。`fmt-3819` 三组共六次均失败，全部保留在分母。六道任务均来自此前使用过的 fmt 开发集合。

早期提取在 `early` / `early_state` 中分别裁剪 38 / 41 次；状态摘要在 `early_state` 的 9/12 条轨迹中触发 10 次。修复、原文行选择和状态摘要分别核算。`early_state` 修复输入节省 1,107,016 Token，两类辅助调用消耗 493,799 Token，最终净减少 613,217 Token。

这组配置同时包含 16K 历史触发水位和状态摘要；其结果反映组合配置的效果。三组每题的任务合同、系统提示与工具定义哈希一致，首次输入的独立基线回执包含不同运行标识、时间和日志，差异逐字段保留。

缓存输入占比从 79.92% 降至 45.57%，非缓存输入从 560,349 增至 1,185,148 Token。报告采用累计输入用量口径，费用保持未定价。

历史批次保留原分母：原五组通过 34/31/33/32/30 条，旧触发五组通过 32/33/32/35/27 条，每组均为 38 条。旧触发实验的状态组观测输入降低 1.36%，实际状态压缩为零次；新提前压缩结果单独归属于已核验的 36 条正式轨迹。

## ReproPatch：恢复、验收与定位

恢复实验的四对均保留原 Run、截止时间、累计预算和账本前缀。到首次模型准入的中位时间为恢复 2.286 秒、重启 97.759 秒；完整 Harness 时长为恢复 1,623.40 秒、重启 1,612.09 秒。较快的启动准入与较高的后续请求开销同时存在。三条失败均为冷构建失败，涉及 `std::ratio` 溢出或 `safe_duration_cast` 模板匹配。

自然假阳性观察值为 0/153；旧产物注入的三次冷拒绝、测试篡改的一次保护路径拒绝，以及回归候选的一次 P2P 拒绝，各自保留场景和分母。15% 自然拦截比例与 60% 恢复净节省目前均缺少对应的实测正结果。

定位实验的首次正确源码曝光主指标覆盖 14/19 道具有 changed-span 的任务。相对原生搜索，有界接口的平均截顶首次命中工具数增加 0.107；反馈排序较有界接口增加 1.321。五道纯插入任务采用独立锚点口径；成功率和 Token 仍使用全部十九题。

## ServiceDesk：业务组件

政策扩展实验的 76 条查询包含 64 条可回答、8 条没有适用政策、4 条无关查询。过滤后 Hit@1 为 96.9%，两个首位错误均为安全补丁查询被证书续期抢占首位，正确政策位于第二位；一条无关查询受 `space` 歧义影响，两组均误召回。零时效不适用返回项描述本批检索的观测。此前真实模型政策任务两组均 4/4，逻辑输入 251,170 → 239,702。

Memory 的两次严格评分失败均来自 `log_summary`：召回字段正确，最终备注省略要求的句点。空结果组通过固定用户脚本取得完整目标备注，可召回组自行组合格式与事实，全部交互和调用纳入用量。正式组模型请求从 138 降至 83，逻辑输入降低约 46.0%，历史偏好补充从 8 降至 0。

对账实验使用合成 Redmine HTTP 服务。每组一百个操作包含五十个首次响应丢失，生产方案保持 100 次提交和零重复，普通重试产生 150 次提交和五十条重复备注。真实 Redmine 权限撤销验收覆盖一个准备进程和三个后继进程，28 项检查通过，两个排队写调用被取消，撤销后的 HTTP 写入尝试为零。

任务账本验收基于当前 ServiceDesk 工作区源码，30 份源码及测试文件哈希与保留快照吻合，25 个定向用例及其测量属性复核通过。120 条待办原始输入为 60,513 UTF-8 字节；ScriptedChatModel 收到的系统与对话消息峰值为 8,689 字节，工具 Schema 单独计量。任务与证据持久化采用生产 SQLite 接线，模型行为与业务后端采用确定性夹具。

CRM 留出基准仍为 A/B 各 11/12；A 的 Agent 逻辑输入 214,692，B 为 262,371，A 少 18.2%。组件定向实验与留出基准使用各自冻结的任务集合。
