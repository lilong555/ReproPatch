## 支持范围

运行环境为 Linux amd64、Python 3.12、本地受信任 Git 仓库及 Docker daemon；WSL2 使用 Docker Desktop Linux 引擎。
验收使用固定 C++ fixture commit、完整 image ID、CMake/CTest 3.28.3 和 GCC 13.3.0。
核心安装只需 PyYAML；自动路径额外固定 openai-agents 0.24.0、openai 3.35.1，完整约束见 requirements/agent.txt。
只接受 Task v2；P1-01 至 P1-07 的源码、预算、隔离、CTest 与报告契约均适用。

`run` 默认 fake，必须有原生 JSON `--mock-script`；真实引擎名为 agents-sdk，模型通过 `--model` 指定。
`sdk` 和 `--model-name` 是可用别名。真实调用必须同时提供 `--allow-paid-model`。
verify-patch、inspect、report 的核心安装不导入 SDK、不读取模型 key。

## 真实模型验收

固定 smoke Task 为 [negative-maximum.live.v2.yaml](../examples/tasks/negative-maximum.live.v2.yaml)。
它使用同一缺陷、测试与保护边界，不向模型提供参考补丁。预算最多 6 个模型 turn、12 次工具、300 秒；
其中 90 秒预留独立验证，单次模型请求上限 45 秒、单条命令上限 60 秒，每轮输出上限 2048 token。
这些执行上限不是精确账单上限；成本未知时保持 null。

已认证组合为用户指定的 `https://api.deepseek.com` 与 `deepseek-flash`。
[供应商模型表](https://api-docs.deepseek.com/quick_start/pricing/) 在本次验收日将其对应到
DeepSeek-V4.1-Flash-1017；API 返回的模型标识为 `deepseek-flash`，没有返回独立的版本证明。
该认证只覆盖本次固定 SDK、模型、Task 与显式环境代理配置；别名升级需重新验收。

先准备计划，不读取 key、不运行 Docker 或模型、不创建 Run：

```bash
python scripts/check_live_gate.py \
  --task examples/tasks/negative-maximum.live.v2.yaml \
  --model deepseek-flash --api-base https://api.deepseek.com \
  --key-env DEEPSEEK_API_KEY --use-env-proxy --output .repropatch/live-smoke/p1-08
```

模型与 HTTPS 端点须由操作者明确选择。
授权覆盖本次模型费用与任务描述、工具 schema、源码/命令输出和原生上下文的发送。
密钥仅通过已选择的环境变量供应，不放入 argv、Task、计划或报告。
客户端默认不信任环境代理；`--use-env-proxy` 显式启用 HTTPX 的代理及 TLS 环境配置。
报告仅保存是否启用的布尔值，不保存代理地址；容器仍断网且不继承模型或代理凭据。

配置与授权确定后，执行同一命令并加 `--execute --allow-paid-model`。
脚本只创建一个新 Run，不自动重试或挑选结果；输出目录必须尚不存在。
它只经生产 Harness / Runner 执行，先做基线，再使用真实 Responses 模型，最后清理并保存实际修复结局。

V-LIVE 通过要求真实引擎、非合成用量、正常 MODEL_FINISHED、清理确认、证据完整，
并至少有一个成功工具结果通过匹配的 provider call_id 进入下一请求且获得后续模型响应。
原生 function_call_output 的关联方式与 [OpenAI 官方文档](https://developers.openai.com/api/docs/guides/function-calling) 一致。
验证器通过哈希读取原生附件，不把模型宣称“完成”当作补丁通过。
接口 gate 与修复 outcome 分别保存；错误补丁或无补丁必须保留真实 REJECTED，不能包装成修复成功。
