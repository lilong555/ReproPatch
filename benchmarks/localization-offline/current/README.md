# 定位离线微基准

固定 12 条查询、每条 5 次重复，模型调用为 0。原生搜索返回 6,419 bytes、目标锚点正文覆盖 12/12；文件摘要加固定下钻返回 97,402 bytes、正文覆盖 11/12。两者的目标文件候选覆盖均为 12/12。该输入上，摘要加固定下钻的体积与执行开销较高；真实 Agent 定位效率、模型 token 消耗及冷验证成功率由在线配对实验测量。

## 输入与方法

输入为 [公开协议](registered/protocol.json) 的三份 fmt 头文件及 12 个预登记定义锚点，源码 commit 为 `0fc31633e7d53ac895ae0a688b83b7d44f0b0c1f`。协议、[输入归档](registered/fmt-input.tar) 和逐文件 SHA-256 均经校验。查询统一使用大小写敏感字面匹配，范围为全部三份头文件。

A 调用生产 `Toolbox.search_code`；B 调用 `Localization(mode="bounded").search`，随后对每个候选文件读取首个命中前 20 行开始的 200 行窗口。选窗只使用响应中的候选信息，评分阶段核对实际返回正文与目标锚点。C 使用同一候选生成器执行无证据回退检查。

每条查询新建定位实例，全部 B 样本的 `cache.hit=false`，计时包含首次缓存构建；缓存复用收益另行测量。C 的本组输入为无执行证据状态。A/B/C 执行顺序按查询与重复轮换，B 下钻随后执行，全部原始样本保留。

## 工具返回

下表为第 1 次重复的 12 条查询合计，字节为 runtime 包装前的规范 UTF-8 JSON。正文与路径列分别统计 JSON 转义后的字符串载荷，其余体积为结构及元数据；原始 UTF-8 载荷另见 [summary.json](summary.json)。候选覆盖与正文覆盖分别计分。

| 条件 | 总 bytes | 正文载荷 bytes | 路径载荷 bytes | 文件候选覆盖 | 锚点正文覆盖 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A 原生搜索 | 6,419 | 3,051 | 1,073 | 12/12 | 12/12 |
| B 文件摘要 | 14,244 | 0 | 312 | 12/12 | 0/12 |
| B 固定下钻 | 83,158 | 81,066 | 312 | 12/12 | 11/12 |

B 共返回 17 个源码窗口。`reserve` 首次匹配位于版权行，固定窗口读取第 1–200 行，目标定义位于第 205 行，正文评分为未命中；[该查询原始记录](raw/r01-q04.json) 保留了候选位置和实际窗口。摘要已有第 205 行位置，模型是否选择继续下钻由在线实验观察。

五次重复中 A 均为 6,419 bytes，B 摘要为 14,244–14,247，B 摘要加下钻为 97,402–97,405，C 摘要为 15,517–15,519。浮点计时字段造成少量序列化长度波动。

## 本机开销与固定格式

计时采用 `perf_counter_ns` / `process_time_ns`，下表为 60 个查询样本的中位数。源码读取、身份校验计入查询成本，实例构造单列；操作系统文件缓存保持自然状态，工作区为只读 `InputWorkspace` 适配器。

| 条件 | 查询墙钟 ms | 查询 CPU ms | 构造墙钟 ms | 每轮读取 bytes |
| --- | ---: | ---: | ---: | ---: |
| A 原生搜索 | 0.458 | 0.456 | 0 | 300,636 |
| B 文件摘要 | 0.662 | 0.661 | 0.034 | 300,636 |
| B 摘要 + 下钻 | 1.037 | 1.035 | 0.034 | 443,730 |
| C 无证据摘要 | 0.676 | 0.675 | 0.028 | 300,636 |

固定候选格式对照保留相同的 59 条匹配记录、candidate ID、正文及顺序，仅改变按文件分组方式：扁平格式 11,041 bytes，分组格式 10,074 bytes，减少 967 bytes（8.76%）；正文载荷均为 3,051 bytes，路径载荷由 1,073 降至 312 bytes。格式化墙钟中位数为 6.838/10.080 微秒，CPU 为 6.017/9.238 微秒；共同匹配流生成的墙钟/CPU 中位数为 0.492/0.491 ms。体积节省与格式化开销均对应这批固定输入。

## 一致性与复现

B/C 候选 ID、顺序、候选池哈希及扫描工作量一致，C 回退原因为 `no_registered_feedback`，共 60/60。固定格式还原相同记录、固定匹配流与生产 A 相同均为 60/60。冻结回放逐一核对 60 组查询的源码曝光、匹配流及 sanity，并确认 A、固定下钻和两种固定格式的字节数一致；摘要总字节随计时字段小幅变化。

精确执行源码封存在 [production-source.tar](production-source.tar)，SHA-256 为 `e84bc9c2643b0a4682adc912118e7888020984e21dbb085e0217786ed157bf61`。[protocol.json](protocol.json) 记录输入、查询与全部代码哈希；[定位实现](../../../src/repropatch/localization.py) 和 [微基准脚本](../../../scripts/benchmark_localization.py) 提供源码入口。[raw/](raw/) 保存逐查询响应、下钻参数、曝光评分、计时和固定候选流，[artifact-hashes.json](artifact-hashes.json) 提供 JSON 证据哈希，[environment.json](environment.json) 记录运行环境。
