# 历史轨迹的压缩机会分布

**现有 fmt 负载已经包含较早的压缩机会，优先调整处理对象与触发时机。** 基线 38 条轨迹全部出现超过 500 代理 Token、经过两步后仍被后续请求携带的工具回执，共 251 条；这些候选在满足年龄条件后仍被携带的次数中位数为 8。48K 历史压缩水位在基线中覆盖 0/38，在全部 190 条中覆盖 2/190，且两次压缩后的修复请求数均为 0。

机会主要集中在文件读取。基线的 207 条 `read_file` 候选贡献了候选后续携带量的 86.3%。固定样例显示，文件定义、编译错误、失败测试和临时文件状态都包含修复证据；适合按当前状态保留关键内容，并为其余内容保留原文入口。

本报告覆盖已完成批次 [42219312911](https://github.com/lilong555/ReproPatch/actions/runs/42219312911)，采用原始 HTTP 请求、供应方 usage、SQLite 事件、工具回执及源码检查点进行离线核对。新增模型请求为 0。

每题每次运行上限为 24 次模型请求。预算终止状态和最终冷验收状态分别统计，预算用尽时已有补丁仍可进入冷验收。

四类测量保存在独立字段中：

1. **供应方实际用量**：逐请求 `input_tokens`、`output_tokens`，包含摘要调用；`cached_tokens` 是输入的组成部分。
2. **运行时触发估计**：从 `pre_send.telemetry` 读取实际估计，并纳入压缩前 plan 的估计。其计算采用既有运行时的 UTF-8/3 与已观测 usage 校准。修复压力峰值单列，摘要请求自身的额外提示在此列之外。
3. **可见文本代理**：固定 `tiktoken==0.12.0`、`o200k_base`，对工具输出字符串和可见组成项分别分词；另保存 UTF-8/3 敏感性结果。加密的不透明内容保留运输字节量。
4. **逐回执投影包络**：固定原有动作序列，把满足长度及年龄条件的回执正文整体替换为带工具状态、源码身份与原文路径的引用，逐条累加代理 Token 差。该值用于衡量待审信息规模，内容选择、重新检索和辅助模型成本由在线对照实验评价。

身份核对串联了 GitHub artifact digest、下载回执、归档清单、逐文件 SHA-256、原生模型输入与 HTTP 请求哈希，以及逐请求 usage 与冻结结果总账。缺失或损坏原件始终保留在期望分母中；本次二者均为 0。

## 单轮候选的规模与内容

候选条件为：**实际首次送入模型的回执超过 500 个 o200k 代理 Token，工具步骤 k 之后完成两步，且在 k+3 或更晚的修复请求中仍实际出现。** 这一规则保留近期证据的消费时间。按 UTF-8/3 复算，基线候选为 263 条、全量为 1,390 条；两种口径的轨迹覆盖均为 38/38 与 190/190。

## 与论文的对应及后续实验

[AgentDiet v2](https://arxiv.org/abs/2509.23586v2) 提供直接的 C++ 任务证据：Multi-SWE-bench Flash 的 40 道 C++ 题中，Claude 4 Sonnet 主 Agent 累计输入降低 39.8%、成功数持平，Gemini 2.5 Pro 降低 70.2%、少通过 1 题。其 500 Token、延迟两步设置支持本次的机会筛选方式；反思模型开销在后续在线实验中逐请求合计。

[ACON v3](https://arxiv.org/abs/2510.00615v3) 在 AppWorld 使用 4,096 历史 / 1,024 观察阈值，主表的 9.93K 是平均峰值指标。当前 48K 的低覆盖与较长后续携带量，支持将触发时间前移。8K、16K 等水位已给出可复算的覆盖分布，新的参数在完整对照实验前冻结。

[The Complexity Trap v3](https://arxiv.org/abs/2508.21433v3) 进一步提供旧观察遮蔽的代码 Agent 证据，也记录了依模型和窗口而变化的成功率。保留路径、行号、源码身份、当前错误及原文回读入口，有助于检验内容筛选后的工程效果。

下一组实验可在相同任务、模型、工具、请求预算与冷验收合同下比较 **baseline / 提前选择性提取 / 提前选择性提取 + 状态摘要**。主要指标继续采用完整任务分母的冷验收与供应方累计输入，全部提取、摘要和回读调用一并计入。既有 fmt 负载已满足机会验证需求；Multi-SWE-bench Flash 的非 fmt C++ 任务适合作为后续跨仓库验证集。
