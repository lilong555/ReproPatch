# nlohmann/json-4537 双头文件入口补充评分

`json4537-header-audit-v1` 用同一个 issue #3915 最小复现程序分别编译并运行
`include/` 与 `single_include/` 入口。原有原生 Oracle 使用默认多头配置，完整
98 项成绩继续保留。本补充评分记录公开分发入口的修复覆盖。

| 候选 | 旧版原生 Oracle | 多头入口 | 单头入口 | 分发完整性 |
| --- | --- | --- | --- | --- |
| 基线 | 未运行 | 失败 | 失败 | 否 |
| 上游参考补丁 | 98/98，通过 | 通过 | 通过 | 是 |
| ReproPatch Full / 批量候选 | 98/98，通过 | 通过 | 失败 | 否 |
| mini 第一轮 | 98/98，通过 | 通过 | 通过 | 是 |
| mini 第二轮 | 98/98，通过 | 通过 | 通过 | 是 |
| mini 第三轮 | 98/98，通过 | 通过 | 通过 | 是 |
| Codex HTTPX 复测 | 98/98，通过 | 通过 | 通过 | 是 |

Full 第一轮、批量候选第二轮和 Full 第三轮的候选补丁哈希相同：
`074990bd9a3c645d6d90500488c8b7bd431b08ea56185b266f75e118db7a04a0`。
它只修改 `include/nlohmann/json.hpp`，多头入口通过，单头入口仍触发父指针
invariant 断言。

补充回归使用 GCC 13.3、`-std=c++11 -O1`、固定 json 工具链镜像、非 root、
断网、只读源码、2 CPU 和 512 MiB 内存。每个入口独立容器执行，容器清理均已确认。
回归源码、候选哈希、镜像及逐项结果见 [JSON 数据](json4537-header-audit.json)。

本评分不调用模型。
